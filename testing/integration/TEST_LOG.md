# Integration — test log

Tests that two or more subsystems work together. There is one test (or more) for every interface listed in TEAM.md section 5. Both owners agree on the test and sign off the result.

See `testing/README.md` for how to run tests and record results.

## Test cases

Define a test here before running it. Test IDs never change.

| ID | What is tested | Requirement / interface | Method | Steps / how | Expected result |
|---|---|---|---|---|---|
| INT-01 | samples flow from S2 to S3 (≥ 5 in 2 s) | IF-01, IF-02 | auto | `subsystem3_test.c` | `[TEST] INT-01 PASS` |
| INT-02 | summary lines flow from S3 to S4 (≥ 2 in 3.5 s) | IF-03 | auto | `subsystem4_test.c` | `[TEST] INT-02 PASS` |
| INT-05 | Line data from S3 reaches the Vehicle Controller every cycle and steers the car | IF-05 | manual (car) | integrated image; follow the line for at least 30 s over rounded corners and junction marks | `vc: t=... zone=Z lost=L jn=J` lines change with the line position; steering follows the zone; `jn=1` at a crossbar |
| INT-06 | GP28 samples from line_sensor_task reach barcode_decode_task (S3 internal) and a barcode is decoded while driving | IF-06 | manual (car) | drive over a printed Code 39 barcode at line-following speed | `BARCODE:` line with the right letter |
| INT-07 | A decoded barcode command from S3 reaches the Vehicle Controller and is used at the next junction | IF-07 | manual (car) | barcode before a junction, map sent from the dashboard | the controller prints the command and turns that way at the junction |
| INT-08 | A line fault reaches the Safety Monitor and stops the car | IF-08, IF-12 | manual (car) | line not found again (e.g. after a bypass, or the car lifted onto white floor) | `vc: line not found, stopped (line fault reported)`, `safety: INHIBIT set (faults 0x2 ...)`, mission FAULT, motors off |
| INT-09 | Line lost on purpose during a bypass does not raise a line fault | IF-09 | manual (car) | obstacle bypass that leaves the line | `lost=1` for the whole detour, no `faults 0x2`, `vc: back on the line` |
| INT-10 | Motion commands from the Vehicle Controller (27-bit word) drive the motors: drive with steering, drive a distance, backwards, stop | IF-10 | manual (car) | line following plus an obstacle bypass (creep forward a set distance, back up, curve) | wheel speeds follow `cmd`/`steer`; `creep done, odometry N mm` close to the distance asked; backing up shows negative wheel speeds |
| INT-11 | The Safety Monitor's motor inhibit stops Motion Control and is released for a newer epoch | IF-11 | manual (car) | stop for an obstacle scan (inhibit while scanning), then drive on | `safety: INHIBIT set`, wheels 0 while set; `safety: inhibit released (a newer epoch is needed to move)`, then the car moves on the new epoch |
| INT-12 | A fault bit from another subsystem (S4 IMU) reaches the Safety Monitor | IF-12 | manual (car) | IMU error while running (seen with a loose IMU wire) | `safety: INHIBIT set (faults 0x4 ...)`, mission FAULT, motors off |
| INT-13 | The Vehicle Controller's status (61-bit frame) reaches the dashboard | IF-13, IF-15 | manual (car + PC) | integrated WiFi image, dashboard open; run barcode, hump and obstacle tests | dashboard shows mission state, barcode count/letter, hump height and obstacle width/distance matching the console |
| INT-14 | Dashboard commands reach the Vehicle Controller, and link loss is reported without a fault | IF-14 | manual (car + PC) | RESUME / PAUSE; hotspot off; hotspot on | `vc: command from the dashboard: RESUME/PAUSE`; `vc: dashboard link down` / `up`; no FAULT |
| INT-15 | MQTT through the kernel WiFi task: connect, send, receive, reconnect and replay | IF-15 | manual (car + PC) | as INT-14, plus sending the barcode map | `mqtt: connected`, `mqtt: subscribed`, `s1: link up, N frame(s) to replay` after a loss; map received (`BARCODE: mapping ...`) |
| INT-16 | Motion status from S2 (28-bit word) is read by the Vehicle Controller (state, done bit, epoch) | IF-16 | manual (car) | obstacle stop and creep | `vc: motion state N` follows the commands (5 = inhibited while scanning); `creep done` when S2 sets the done bit |
| INT-17 | Odometry from S2 reaches S4 and is used for the hump height | IF-17 | manual (car) | drive the right wheel over the 23 mm hump while line following | S4 `odo_mm` rises with the car, `odo_forward=1` on the hump, `height_valid=1` |
| INT-18 | The barcode map sent from the dashboard (S1) is used by the S3 decoder | IF-18 | manual (car + PC) | send a map while READY, drive over the barcode; repeat with the letter remapped | `BARCODE: mapping F U L R` matches the dashboard; the same letter gives the remapped command |

INT-01 and INT-02 are the template's example interfaces (IF-01..IF-04, marked *example* in TEAM.md); S3 used the same IDs inside its own tests (now S3-I01, S3-I02). INT-05..INT-18 are numbered after the interface they test. **manual (car)** = observed on the integrated car, from the console log.

*Method:* **auto** = `TEST_CHECK` in code, result printed on the console;
**manual** = a person observes the result (LED, scope, meter, phone app…).
